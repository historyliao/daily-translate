# 翻译总开关与模式设计

## 目标

Popup 使用一个“开启翻译”总开关和一个“当前页面模式”配置，替代“自动翻译”和独立页面控制入口。

翻译模式分为：

- `划词翻译`：用户选择网页文字后显示悬浮译文；
- `滑动窗口翻译`：翻译当前视口的网页文字，滚动后继续翻译新进入视口且尚未处理的内容；
- `整页翻译`：翻译当前页面全部已加载、可渲染的普通文本并监听后续变化。

## 配置与兼容性

继续使用 `chrome.storage.local.translationEnabled` 作为唯一扩展级总开关。`translationMode` 由每个 Content Script 文档实例在内存中独立维护：

- `selection`：划词翻译；
- `viewport`：滑动窗口翻译；
- `page`：整页翻译。

`translationEnabled` 缺失时默认开启。每个新标签页、新文档、刷新页面以及 SPA 的路径或查询参数变化都默认使用 `selection`，仅 Hash 变化保留当前文档模式，因此不会因其他页面曾使用页面翻译而自动产生批量请求。

所有普通页面通过 Storage 事件同步响应总开关和目标语言。Popup 通过 Service Worker 查询或修改当前活动标签页的模式，模式不写入 `chrome.storage.local`，也不传播到其他页面。

## 状态行为

```text
translationEnabled=false
    -> 不创建任何翻译请求
    -> 取消当前划词和滑动窗口请求
    -> 恢复滑动窗口翻译替换的原文

translationEnabled=true + translationMode=selection
    -> 只启用划词翻译

translationEnabled=true + translationMode=viewport
    -> 关闭划词浮层并取消划词请求
    -> 立即翻译当前可见区域
    -> 滚动、缩放或动态加载后继续翻译新内容

translationEnabled=true + translationMode=page
    -> 关闭划词浮层并取消划词请求
    -> 翻译当前页面全部已加载、可渲染的普通文本
    -> 监听页面后续新增、变化或变为可见的内容
```

从页面翻译模式切换到 `selection` 时，取消批量请求并恢复原文。从 `selection` 切换到页面翻译模式时，取消划词请求并开始扫描。目标语言变化时先恢复原文，再把当前文档重置为 `selection`，不会自动重新发起页面翻译。

## Popup

控制页依次展示：

- “开启翻译”总开关及“已开启/已关闭”状态；
- “当前页面模式”下拉框，选项为“划词翻译”“滑动窗口翻译”和“整页翻译”；
- 目标语言；
- 打开设置。

总开关关闭或当前页面不支持 Content Script 时禁用模式下拉框。Popup 打开时查询活动标签页的当前模式，修改模式时只向该标签页发送消息。

Service Worker 的工具栏 Badge 继续显示 `ON`/`OFF`，标题只显示总开关状态。

## 滑动窗口翻译

### 文本扫描

开启时立即扫描，滚动、窗口缩放和 DOM 变化后使用 300ms 防抖再次扫描。只处理顶层 HTTP/HTTPS 页面中与视口相交、包含 Unicode 字母的普通文本节点。

跳过脚本、样式、表单控件、可编辑区域、代码块、SVG、Canvas、插件浮层、隐藏内容和 iframe。单个文本节点正文超过 3000 个字符时跳过。

### 批次与去重

新节点按文档顺序分批，每批最多 50 个节点且正文累计不超过 3000 个字符，批次串行请求。每个节点记录原文、译文和处理状态：

- 已记录节点再次进入视口时跳过，不重复消耗 Token；
- 网页自行更新节点时移除旧记录，新内容再次可见后重新翻译；
- 结果返回时节点内容已变化则丢弃该项，不覆盖网页新内容；
- 关闭或切换模式时，只恢复当前值仍等于插件译文的节点。

### 过程反馈

批次请求期间在页面右下角显示当前区域的段落进度，并通过独立 Shadow DOM 浮层为当前批次文本绘制淡蓝色范围标记。标记使用文本 Range 的可见矩形，不包裹网页节点、不修改网页元素样式，也不参与文本扫描。

每批完成后更新进度；当前队列完成后短暂显示已翻译段数和耗时并自动隐藏。滚动或缩放时重新定位正在处理的范围标记。批次失败时显示错误提示；关闭总开关、切换模式或 Content Script 替换时立即清理提示和标记。

### 模型请求

Content Script 继续使用现有 `translation` Port，发送：

```text
{ type: "translate-batch", items: [{ id, text }] }
```

Service Worker 复用现有配置读取、OpenAI-compatible Chat Completions、流式解析、取消、Token、延迟和日志逻辑。模型返回严格的 ID 到译文 JSON 映射；流式模式缓存完整内容并在 `[DONE]` 后校验。

批次失败时保留原文并显示一次简短提示，本次模式会话不自动重试。日志不保存网页原文或译文。

## 调用链影响

- Popup 通过 Storage 读写 `translationEnabled`，通过 Service Worker 查询和修改活动标签页的 `translationMode`。
- Content Script 初始化时只读取总开关，并将当前文档模式初始化为 `selection`；Storage 变化只同步总开关和目标语言。
- `handleMouseUp()` 只在总开关开启且模式为 `selection` 时进入原有划词请求。
- 滑动窗口和整页翻译只在总开关开启、当前文档使用对应模式且标签页处于活动状态时运行；标签页失焦时保留已完成译文和队列，切回后继续。
- Service Worker 的单文本和批量请求继续共用一个 Port 入口和网络请求实现，不新增权限。

## 验证

- 验证新文档不读取旧的全局 `translationMode`，始终使用划词翻译。
- 验证总开关关闭时三种模式均不请求 API，且页面翻译译文恢复。
- 验证三种模式互斥切换，目标语言变化后恢复原文并重置为划词翻译。
- 验证标签页失焦时取消在途请求但保留已完成译文和队列，切回后继续且不重复翻译已完成内容。
- 验证首次扫描、滚动新增、动态内容、去重、50 节点和 3000 字符批次边界。
- 验证合法、缺失、重复、未知 ID 和空译文响应。
- 验证流式与非流式批量请求继续记录 Token、延迟和日志。
- 执行 JavaScript 语法、Manifest JSON、Popup 元素绑定和 `git diff --check`。
- 在加载当前工作区扩展的 Chrome 中手动验证 Popup、划词、滑动、整页、标签页切换、滚动去重、恢复和网络请求。
