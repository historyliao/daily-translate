# 整页翻译模式设计

## 目标

在现有“划词翻译”之外提供“整页翻译”模式。整页模式首次处理当前页面全部已加载、可渲染的普通文本，后续增量处理新增、变化或刚变为可见的内容，不依赖滚动位置，也不定时扫描整个页面。

## 配置与交互

每个 Content Script 文档实例在内存中维护当前页面的 `translationMode`，合法值为：

- `selection`：划词翻译；
- `page`：整页翻译。

Popup 的“当前页面模式”下拉框提供“整页翻译”。Popup 打开时向活动标签页查询模式，修改时只通知该标签页，不把模式写入 `chrome.storage.local`。新标签页、新文档、刷新以及单页应用的 `pathname` 或 `search` 变化均默认使用 `selection`；仅 Hash 变化保留当前模式。总开关开启且当前文档模式为 `page` 时，仅最后获得焦点的 Chrome 窗口中的活动标签页开始整页翻译。

标签页或 Chrome 窗口切换时，旧活动页取消在途请求并隐藏进度反馈，但保留已完成译文、节点记录和待处理队列；切回后继续处理未完成内容，不重复请求已完成且未变化的节点。其他页面不会继承当前页的 `page` 模式，避免未经用户主动选择就消耗 API Token。

整页翻译期间：

- 首次扫描全部已加载、可渲染的普通文本，包括当前屏幕外的内容；
- 页面新增内容后自动翻译新增子树；
- 已存在的隐藏内容在展开或变为可见后自动翻译；
- 网页原地修改已处理文本后翻译新内容；
- 滚动本身不触发扫描或请求；
- 进度浮层显示当前请求阶段、待处理数量和已显示数量；
- 当前队列完成后持续显示已翻译段落数并监听页面变化，失败时显示暂停状态。

关闭总开关或切换到其他模式时，取消当前请求、停止增量监听并安全恢复原文。目标语言变化时执行相同清理，并把当前页面重置为 `selection`；用户需要重新主动选择页面翻译模式。

## 文本范围

首次扫描从 `document.body` 开始，处理全部已加载且当前可渲染的普通文本节点，不要求节点与视口相交。

继续跳过：

- `script`、`style` 和 `noscript`；
- `input`、`textarea`、`select` 和 `option`；
- `code`、`pre`、`kbd` 和 `samp`；
- SVG、Canvas、iframe 和插件浮层；
- 可编辑区域；
- 空白、纯数字、纯标点及不含 Unicode 字母的文本；
- 超过 128 个文本节点或 12000 字符的自然段（保留整段原文、记录错误并暂停）；
- 当前仍不可渲染的隐藏内容。

iframe 不在顶层 Content Script 的处理范围内。尚未加入 DOM 的内容在后续加入时处理；隐藏内容在相关元素的 `class`、`style`、`hidden`、`aria-hidden` 或原生折叠区的 `open` 状态变化并成为可渲染内容后处理。隐藏判断包含祖先的透明度、显示状态和关闭的折叠区。

## 增量监听与节点状态

整页模式使用 `MutationObserver` 获取局部变化，不通过定时任务遍历和比较整页：

- `childList`：只扫描新增节点对应的子树，并清理已删除子树的节点记录；
- `characterData`：只检查发生变化的文本节点；
- `attributes`：只在 `class`、`style`、`hidden`、`aria-hidden`、`open` 或 `contenteditable` 变化时扫描对应元素子树。

增量通知按 300ms 窗口合并；同一节点和互相包含的子树只扫描一次，收集完成后再启动批量请求。后续通知不推迟已安排的扫描，避免持续更新使队列一直等待。停止模式时清理待扫描子树及定时器。扫描跳过脚本、代码块和插件自身等被排除的子树。

每个进入处理流程的文本节点沿用节点记录表，保存原文、译文和处理状态：

- 当前值等于插件写入的译文时，视为插件自身触发的 DOM 变化并忽略；
- 尚在排队或请求中的节点收到通知，但原文未变时保留记录，不重复请求或使当前响应失效；
- 当前值被网页改成其他内容时，删除旧记录并将新内容重新入队；
- 已处理且内容未变化的节点跳过；
- 节点删除后清理对应记录；
- 响应返回时节点已断开或内容已经变化，则丢弃该节点的响应结果。

节点去重只比较事件涉及的节点，不进行全页面内容对比。

## 请求与反馈

整页模式复用现有 `translate-batch` Port 协议、OpenAI-compatible Chat Completions 请求、目标语言配置、流式开关、响应 ID 校验、Token 统计、延迟指标和运行日志。

整页模式只在活动标签页按队列顺序逐自然段串行执行，当前段落及补译结束后才请求下一段。后台在标签页和窗口焦点变化时先向所有非活动普通网页发送停用消息，完成后再激活当前页；内容脚本初始化时也向后台确认自身是否为活动标签页。以最近的非 inline/contents 容器识别段落，为节点附加 paragraphId 并按文档顺序组织；不同段落不放入同一请求。单段请求上限为 128 个节点、12000 字符，超过上限时保留整段原文、记录错误并暂停，不拆分当前段落或越过它继续处理后续内容。所有在途请求单独管理；关闭或切换模式时彻底停止并恢复原文，标签页失去活动状态时只取消请求并把请求中的记录恢复到队首。会话 ID 保证已取消的旧异步流程不能回填译文或更新进度。

模型按同一 paragraphId 的完整上下文理解句子，再将译文分配给原节点 ID，不修改 DOM 元素或事件。局部更新时可通过 paragraphs 提供段落原文上下文；读取上下文时跳过隐藏、代码等排除内容，并将插件已写回的译文还原为所持有的原文用于请求。完整节点都在本次请求中时不额外重复提供上下文；额外上下文总预算为每请求 12000 字符，超预算则省略。只有一个段落文本节点的请求直接使用纯文本译文，流式片段实时显示，诊断类型为 paragraph；多节点段落保留 JSON 输出，但只在全部结果有效后一次性写回。

批量请求超时为 60 秒，划词请求保留 30 秒。非流式按完整响应计时；流式收到译文或非空 `reasoning_content` 时刷新超时，思考片段不作为译文显示或保存，不触发 TTFT。读取非流式响应体时的中止保留为取消或超时，不归类为无效响应。

每次 API 调用持有独立网络 AbortController，批次取消向当前调用传播；调用超时或失败仅中止该调用，保留原始错误分类，不误取消后续补译。异常路径在写监控前中止网络，finally 再确保清理连接、计时器和取消监听；流式读取退出时释放 reader 锁。批次顶层失败也会中止批次控制器后再向页面报告错误。

模型参数由设置页的 `modelParameters` JSON 对象提供，统一合并到划词、整页和段落补译请求。插件不再固定发送 `temperature` 或 DeepSeek `thinking`；用户可按模型文档配置这些参数来权衡速度、质量和输出长度。`model`、`messages`、`stream`、`stream_options` 与 `response_format` 仍由插件管理，不能被模型参数覆盖。

官方 DeepSeek V4 的批量翻译由插件启用 `response_format: {type: "json_object"}`，划词请求不启用。JSON 输出仍需校验条目数、ID 唯一性及非空译文，不通过位置猜测对应关系。错误日志区分 API 响应格式、空响应、批量 JSON、条目数、ID、空译文及 `finish_reason=length` 导致的输出截断，并提供可展开的请求阶段、HTTP 状态及校验详情。API 报错直接展示 HTTP 错误正文或响应中的 `error` 内容，脱敏当前 Token 和 Bearer 凭据，超过 8192 字符时截断并标注；不主动记录原文、译文或思考内容，但服务端错误可能回显请求文本。依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode)。

整页模式复用现有进度浮层和当前批次文本高亮。屏幕外文本没有可见矩形时不绘制高亮，但仍参与翻译和进度统计。

后台通过 batch-status 发送补译序号和总数，页面显示“正在请求”或“正在补译 X/Y”及待处理数量。在任务及 Port 尚未结束时不切换为空闲或失败结束态。空闲汇总从当前仍连接的节点记录计算，持续显示“当前无请求 · 监听页面变化”及已翻译数量；当前段落最终失败时切换为“翻译已暂停”，显示已翻译及剩余段落数。暂停期间增量监听仍收集变化，但不再发请求；关闭后重新开启才重置状态并重新扫描。整页空闲及失败面板不定时隐藏。该状态只描述当前页面，Token 监控仍是所有标签页汇总。

`batch-chunk` 只用于单节点段落的纯文本流式预览，失败时仅恢复仍由插件持有且未被页面自行修改的原文。多节点段落不发送中间条目，最终响应必须包含全部请求 ID 和非空译文，校验完成后在同一消息处理中统一写回，避免页面出现半段译文。

JSON 可解析且 ID 对应关系明确时，对遗漏条目、缺字段或空译文各单独补译一次。补译提供可用的同段原文上下文，只请求目标片段的纯文本译文，30 秒超时，在当前段落内串行执行，关闭翻译一并取消；原请求和每次补译分别统计用量与延迟。所有补译成功后才按原始 ID 顺序返回完整段落，已经恢复的初始格式异常不记录为最终错误。任一补译仍失败时抛出包含初始异常和各补译失败详情的汇总错误，不发送部分结果，页面保留整段原文并暂停后续请求。

## 调用链影响

```text
Popup 向当前活动标签页发送 translationMode="page"
        |
        v
Service Worker 将模式消息转发给当前活动标签页
        |
        v
活动页 Content Script syncTranslationBehavior()
        |
        +--> 首次扫描 document.body
        |
        +--> MutationObserver 增量提供新增或变化的局部节点
                        |
                        v
                 批量翻译队列
                        |
                        v
        Service Worker translate-batch
                        |
                        v
        校验响应 ID 并替换对应文本节点
```

- Popup 和 Service Worker 的模式合法值包含 `page`，但模式不进入全局存储；
- 页面替换模式只允许当前活动标签页启动，标签页或窗口切换时暂停旧页后再激活新页；
- `handleMouseUp()` 仍只允许 `selection` 模式进入划词请求；
- 整页模式不在滚动事件中安排扫描，只在首次启动和 DOM 增量事件中收集节点；
- 标签页失焦只取消在途请求并保留已完成译文，切回后从等待队列继续；
- 停止模式后，只有节点当前值仍等于插件译文时才恢复原文，避免覆盖网页自己的更新。

## 验证

- 新标签页、新文档、刷新、离开后通过往返缓存恢复，以及 SPA 的路径或查询参数变化时默认使用划词翻译，Hash 单独变化时保留模式；
- Popup 只读写当前活动文档的模式，不读写全局 `translationMode`；
- `page` 模式无需滚动即可处理页面顶部和屏幕外的已加载文本；
- 多个普通网页标签页同时打开时，仅最后获得焦点的 Chrome 窗口中的活动标签页发起页面翻译请求，其他页面不会继承它的模式；
- 标签页失焦时取消在途请求、保留已完成译文和等待队列，切回后继续且不重复翻译已完成节点；
- 新增 DOM、隐藏区域展开和文本原地更新后只处理相关内容；
- 已处理且未变化的节点不重复请求，滚动不产生新的整页请求；
- 整页模式按段落组织，每次只请求一个自然段，单段上限为 128 个节点、12000 字符；单节点段落走纯文本流式路径，多节点段落完整成功后一次写回，当前段落及补译结束才启动下一段；
- 当前段落最终失败或超过上限时保留整段原文、暂停后续请求，关闭后重新开启才能重试；
- 流式和非流式批量响应均可应用并记录 Token、延迟和日志；
- 思考片段刷新流式超时但不展示、不计入 TTFT；官方 DeepSeek V4 专用参数不发送到其他服务；
- 关闭总开关、切换模式和修改目标语言时取消请求并安全恢复原文，目标语言变化后回到划词模式；
- 划词模式既有行为保持不变；
- 执行 JavaScript 语法、Manifest JSON、Popup 元素绑定、`git diff --check` 和 DOM 冒烟验证；
- 不使用 Chrome DevTools，真实 Chrome 交互由用户同步代码后手动确认。
