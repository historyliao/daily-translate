# Daily Translate（每日翻译）

本地运行，数据私有，翻译由你掌控。

Daily Translate 是一款本地运行、数据私有、完全自主控制的开源 AI 网页翻译与文本解读 Chrome 插件。划词后可按需翻译或开启多轮解读，亦可翻译整个页面；插件可连接主流模型服务商，也可接入本地、内网或云端部署的自定义模型 API。插件无需账号或额外后台，配置、Token、监控指标和日志均保存在 Chrome 本地；需要处理的文本仅发送到你指定的 API 服务，数据流向由你掌控。

- 本地运行：插件直接在 Chrome 中运行，无需注册账号或额外部署插件后台
- 私有存储：API 配置、Token、用量统计、延迟指标和运行日志均保存在 Chrome 本地
- 两种页面模式：划词工具提供按需翻译和可追问的多轮解读，整页翻译用于连续阅读全文
- 服务自主选择：内置多家模型服务商，也支持本地、内网、代理或云端自定义 API；待处理文本仅发送到用户指定的服务
- 模型自由配置：服务商、API 类型、Base URL、Token、Model 和模型参数均可配置，不绑定模型或 API 服务商
- 多协议适配：通过开源 `pi-ai` 适配 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generative AI 和 Mistral Conversations
- 展示时机可控：默认等待模型完整输出后显示，也可开启实时显示结果
- 用量与延迟监控：本地统计 Token 消耗、TTFB、TTFT、完成耗时、P50 和 P95，并记录运行错误
- 开源透明：基于 MIT License，代码和数据处理路径均可检查、修改和自行维护

## 安装

Chrome 不能直接加载项目源码。源码依赖 npm 包，必须先将依赖打包成浏览器可识别的文件，再加载生成的扩展目录。

```text
项目根目录/                 源码目录，不能加载到 Chrome
└── build/extension/       构建产物，加载这个目录
```

安装前需要 Node.js 22.19 或更高版本。先确认 Node.js 版本，然后在项目根目录安装依赖并构建：

```bash
node --version
npm install --ignore-scripts
npm run build
```

构建成功后应当生成 `build/extension/manifest.json`。然后：

1. 打开 Chrome 的 `chrome://extensions`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目的 `build/extension/` 目录。
4. 确认扩展加载成功后，打开扩展的“详情”，进入“扩展程序选项”配置模型服务。

如果源码在远程开发机器上，应当先在远程机器完成构建，再把整个 `build/extension/` 目录复制到本地。必须同时复制其中的 `background/`、`content/`、`popup/`、`options/` 和 `icons/` 等全部内容，不能只复制 `manifest.json` 或单个脚本。然后在本地 Chrome 中选择复制后的目录。

## 配置

填写翻译服务配置并保存：

- `服务商`：选择内置服务商，或选择“自定义服务”。内置服务商包括 DeepSeek、OpenAI、Anthropic、Google、OpenRouter、xAI、Groq、Cerebras、Mistral、NVIDIA、Together AI、Fireworks、Hugging Face、Moonshot/Kimi、MiniMax、Z.AI、Baseten 和 Vercel AI Gateway。
- `API 类型`：仅自定义服务需要选择；支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generative AI 和 Mistral Conversations。
- `Base URL`：模型服务地址。选择内置服务商时自动填入默认地址，也可以改为代理、内网网关或本地部署地址。例如 DeepSeek 使用 `https://api.deepseek.com`，OpenAI 使用 `https://api.openai.com/v1`，Anthropic 使用 `https://api.anthropic.com`，Google 使用 `https://generativelanguage.googleapis.com/v1beta`，Mistral 使用 `https://api.mistral.ai`。
- `Token`：API 访问令牌。
- `Model`：可以从内置模型建议中选择，也可以手动填写服务商尚未收录的模型标识。
- `模型参数（JSON）`：可选，支持 `temperature`、`maxTokens`、`reasoning`、`thinkingBudgets` 和 `samplingParams`。例如 `{"temperature": 0, "maxTokens": 2048, "reasoning": "low", "samplingParams": {"top_p": 0.9}}`。
- `实时显示结果`：默认关闭，等待模型完成后一次显示；开启后随模型的输出片段逐步显示。底层请求和响应格式由所选 API 适配器处理。
- `目标语言`：点击工具栏中的插件图标，在“控制”页选择；默认是简体中文。

Token 只保存在 Chrome 的 `storage.local` 中，由后台 Service Worker 读取，不会注入网页内容。插件直接调用你配置的模型服务，不经过 Daily Translate 自有服务器，也不向集中控制台上报配置、文本、译文、统计或日志。

## 使用

在任意普通 HTTP/HTTPS 网页中选中包含文字的文本，插件会先在选区附近显示“翻译 / 解读”操作条，此时不会调用模型或消耗 Token。点击“翻译”显示目标语言译文；点击“解读”打开对话框，自动解读选中文字并支持继续追问。纯数字、标点、空白和 Emoji 不显示操作条。

点击浏览器工具栏中的插件图标打开控制面板，可以统一启用或停用功能，并选择当前页面的工作模式：

- 绿色 `ON`：启用当前工作模式。
- 灰色 `OFF`：所有工作模式都不调用 API，不消耗 Token。
- `划词工具`：选中文字后按需选择单次翻译或多轮解读；两种结果都使用控制面板中设置的目标语言。
- `整页翻译`：翻译当前页面全部已加载、可渲染的普通文本，并继续处理动态新增或变为可见的内容。

工作模式只对当前页面生效。新建标签页、打开其他网页、刷新页面，或单页应用的路径和查询参数变化后，均默认回到划词工具；只有主动选择整页翻译时才切换模式，仅 URL Hash 变化时保留当前模式。翻译、解读和追问请求共用 Token、延迟和错误日志统计。

首次解读会把选中文字、最多 200 字符的页面标题，以及选区所在文本块附近最多 1200 字符的上下文发送给用户配置的模型服务。上下文只用于判断选中文字的实际含义，不要求模型解释未选中内容；划词翻译仍然只发送选中文字。每次追问都会重新发送当前会话的完整可见历史，因此输入 Token 会随对话轮数增长。解读不设置固定追问轮数；单条消息最多 12000 字符，会话可见文本合计最多 50000 字符，达到字符上限后需要重新选择文字。

解读会话只存在于当前网页的内存中，不写入 Chrome 存储或运行日志。关闭对话框、按 `Escape`、重新选择其他文字、停用插件、切换模式、刷新或跳转页面后，旧会话及在途请求立即结束，不能恢复。对话框打开后，点击网页其他区域不会关闭它；翻译浮层和划词操作条仍可通过点击外部区域关闭。

整页翻译只在最后获得焦点的 Chrome 窗口的活动标签页中运行。切换标签页或 Chrome 窗口时，插件会取消旧标签页的在途请求，但保留已经完成的译文、节点记录和待处理队列；切回后从未完成内容继续，已完成且未变化的文本不会重复请求。其他标签页不会因当前页选择了整页翻译而自动开始翻译。划词工具不受此切换逻辑影响。

停用功能会立即取消正在进行的请求、关闭划词浮层并恢复页面翻译替换的原文。重新启用后，已打开的网页无需刷新即可继续使用。需要修改 API 配置时，点击控制面板中的“打开设置”。

使用整页翻译时，需要在当前页面的控制面板中主动选择该模式。插件会在首次进入模式时处理页面中已经加载的全部可渲染普通文本，包括屏幕外内容。页面后续新增内容、原地更新的文本，以及通过 `class`、`style`、`hidden`、`aria-hidden` 或原生折叠区展开后变为可见的内容会自动翻译。短时间内的页面更新会合并后分批处理，重复通知不会重复请求；滚动本身不会触发扫描。已翻译且未变化的文本不会再次请求 API。

整页翻译按段落组织上下文：同一段落内被链接、加粗等行内元素分开的文字放在一起交给模型理解，按原文本节点写回，不替换元素、链接或事件。普通段落不跨批次；仅局部文字变化时，可附带该段原文作为上下文，已经成功且未变化的文字不会再次要求模型翻译。上下文也会产生输入 Token。

活动标签页按队列顺序逐自然段串行请求，当前段落及其补译全部结束后才发起下一段请求，不会把不同段落混入同一请求。段落只有一个文本节点时，直接使用纯文本请求；开启实时显示后译文会边返回边显示，否则完成后一次显示。包含多个文本节点时使用 JSON 批量请求，必须取得该段全部有效译文后才一次性写回。最终 JSON 损坏、ID 存在歧义、请求中断或补译仍失败时，不会保留该段的部分译文。

整页状态面板持续显示“正在请求”“正在补译 X/Y”、待处理数量或“当前无请求 · 监听页面变化”。当前段落最终失败后，面板会显示“翻译已暂停”，该页面不再请求后续段落；关闭翻译后重新开启可从原文重新扫描和重试。失败暂停期间仍记录页面新增或修改的内容，但不会自动恢复请求。标签页失焦造成的暂停不会恢复原文，切回后自动继续；关闭总开关、切换模式或修改目标语言会停止监听、恢复原文并移除面板，其中修改目标语言还会把当前页面重置为划词工具。监控中的 Token 是所有标签页的汇总，不表示当前页面仍在请求。每次 API 调用退出时都会清理网络连接；取消已发出的请求不保证服务商停止已开始的生成或计费。

每次整页请求只处理一个自然段，单段上限为 128 个文本节点、12000 字符。超过上限时保留该段原文、记录错误并暂停后续翻译，不拆分段落，也不越过它继续处理后面的内容。额外上下文每请求最多 12000 字符，超过预算时不附带额外上下文。整页请求超时为 60 秒，划词请求为 30 秒；收到译文或思考片段时会刷新超时计时，思考内容不展示、不存储，也不计入 TTFT 的首个译文时间。实际速度取决于页面结构、模型及服务端能力，段落上下文可以改善连贯性，但不保证模型译文质量。

批量 JSON 可解析且 ID 对应关系明确时，仅对缺失条目、缺字段或空译文的条目各补译一次。补译带上可用的同段上下文，要求只返回目标片段的纯文本译文，超时为 30 秒，不重复请求已经取得的条目，额外用量和延迟照常计入监控；补译在当前段落内串行执行，关闭翻译会一并取消。所有补译成功后才提交整个段落；任一补译仍失败则保留整段原文、暂停后续翻译并记录汇总错误。错误详情中的 `invalidItems` 和 `retryFailures` 会分别列出初始异常条目及补译失败原因，帮助定位模型返回格式或 API 问题。

模型参数统一用于划词翻译、划词解读、整页翻译和段落补译请求。例如可使用 `{"temperature": 0}` 降低随机性，使用 `{"maxTokens": 2048}` 控制最大输出长度，或通过 `reasoning` 和 `thinkingBudgets` 权衡响应速度与输出质量。`samplingParams` 用于传入 `top_p` 等 pi 未统一建模的 OpenAI-compatible 采样参数。不同服务支持的字段和值不同；不支持的参数会由模型服务返回原始错误。模型、消息、Token、取消信号、重试策略和实时展示行为由插件管理，不能通过模型参数覆盖。

遇到翻译错误时，控制面板日志会区分空译文、JSON 格式错误、批量条目数或 ID 不匹配、输出长度截断等原因。模型服务报错会直接展示 pi 适配器保留的原始错误正文；当前配置的 Token 和 Bearer 凭据会脱敏，超过 8192 字符的错误内容会截断并标注。展开“错误详情”可查看失败阶段、错误代码、服务商、API 类型、API 主机、实时展示状态、HTTP 状态、返回字符数、耗时、模型结束原因及批量校验细节。插件不主动记录原文、译文或思考内容，但服务端错误可能回显请求文本，分享日志前请检查。JSON 输出约束不能保证条目完整，插件仍会校验每个 ID，避免将译文写到错误位置。

插件不处理 Chrome 内部页面、Chrome Web Store、`input`/`textarea` 选区，也不提供翻译历史。

## 监控指标

控制面板的“延迟”页展示以下指标：

- `TTFB`：从发起 API 请求到收到响应头的耗时，包括浏览器网络处理、连接建立、服务端排队以及服务端开始响应前的时间；API 适配器不提供响应头回调时显示 `--`。
- `TTFT`：从发起 API 请求到收到第一个非空模型输出片段的耗时。关闭实时显示时仍会统计，只是不立即更新页面。
- `完成耗时`：从发起 API 请求到 pi 适配器确认完整响应结束的耗时。
- `P50`：50% 的成功请求完成耗时不超过该值，反映典型请求体验。
- `P95`：95% 的成功请求完成耗时不超过该值，用于观察较慢请求的尾部体验。

历史平均完成耗时基于全部历史成功请求。P50 和 P95 基于最近最多 500 次成功请求。失败、超时和取消请求只计入请求结果数量，不参与平均值或百分位数计算。这些指标是浏览器侧观测的 API 请求耗时，不代表模型的纯推理耗时，也不包含 Token 统计和日志写入时间。

## 升级插件

如果插件目录是通过 Git 克隆的，在项目目录中更新代码：

```bash
git switch main
git pull --ff-only origin main
```

更新源码后需要重新构建：

```bash
npm install --ignore-scripts
npm run build
```

每次构建都会重新生成整个 `build/extension/`，不要直接修改其中的文件。如果 Chrome 与源码位于同一台机器，打开 `chrome://extensions`，找到本插件并点击“重新加载”即可，无需卸载扩展。

如果在远程机器开发，重新构建后还需要把完整的 `build/extension/` 再次复制到本地，覆盖上次复制的构建目录，然后在 Chrome 中点击“重新加载”。只更新源码而不重新构建、只复制部分文件，或者只点击 Chrome 的“重新加载”，都不会更新实际运行的扩展代码。

插件会为已经打开的普通 HTTP/HTTPS 页面自动恢复内容脚本，通常无需刷新网页；如果页面受 Chrome 注入限制或仍显示旧版本错误，请手动刷新该页面。

如果插件目录不是 Git 仓库，请用新版本源码完整覆盖原目录、重新安装依赖并构建，再到 `chrome://extensions` 中重新加载插件。插件加载期间不要删除或移动 `build/extension/` 及其所属项目目录。
