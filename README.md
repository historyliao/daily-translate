# Daily Translate（每日翻译）

本地运行，数据私有，翻译由你掌控。

Daily Translate 是一款本地运行、数据私有、完全自主控制的开源 AI 网页翻译 Chrome 插件。支持划词、滑动窗口和整页翻译，可连接本地、内网或云端部署的 OpenAI-compatible API，自由指定 Base URL、Token 和模型。插件无需账号或额外后台，配置、Token、监控指标和日志均保存在 Chrome 本地；需要翻译的文本仅发送到你指定的 API 服务，数据流向由你掌控。

- 本地运行：插件直接在 Chrome 中运行，无需注册账号或额外部署插件后台
- 私有存储：API 配置、Token、用量统计、延迟指标和运行日志均保存在 Chrome 本地
- 三种翻译模式：支持划词翻译、滑动窗口翻译和整页翻译，适应单词查询、阅读辅助和全文浏览
- 服务自主选择：支持本地、内网或云端部署的 OpenAI-compatible API，翻译文本仅发送到用户指定的服务
- 模型自由配置：Base URL、Token 和 Model 均可配置，不绑定模型或 API 服务商
- 流式与非流式响应：可根据模型服务能力切换，默认使用兼容性更好的非流式模式
- 用量与延迟监控：本地统计 Token 消耗、TTFB、TTFT、完成耗时、P50 和 P95，并记录运行错误
- 开源透明：基于 MIT License，代码和数据处理路径均可检查、修改和自行维护

## 安装

1. 打开 Chrome 的 `chrome://extensions`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目目录。
4. 点击扩展详情中的“扩展程序选项”。

## 配置

填写翻译服务配置并保存：

- `Base URL`：OpenAI-compatible API 的版本根地址，例如 `https://api.openai.com/v1`。
- `Token`：API 访问令牌。
- `Model`：模型名称，例如服务商提供的模型标识。
- `启用流式响应`：可选，默认关闭；开启后译文会随模型输出逐步显示，API 服务需支持 Chat Completions SSE 响应。
- `目标语言`：点击工具栏中的插件图标，在“控制”页选择；默认是简体中文。

Token 只保存在 Chrome 的 `storage.local` 中，由后台 Service Worker 读取，不会注入网页内容。

## 使用

在任意普通 HTTP/HTTPS 网页中选中包含文字的文本，插件会自动识别源语言，请求配置的大模型 API，并在选区附近显示目标语言译文。点击浮层外的页面区域即可关闭浮层。纯数字、标点、空白和 Emoji 不会触发翻译。

点击浏览器工具栏中的插件图标打开控制面板，可以统一开启或关闭翻译，并选择翻译模式：

- 绿色 `ON`：按当前模式执行翻译。
- 灰色 `OFF`：所有翻译模式都不调用 API，不消耗翻译 Token。
- `划词翻译`：选中文字后显示悬浮译文。
- `滑动窗口翻译`：翻译可见区域，滚动时继续翻译尚未处理的内容。
- `整页翻译`：翻译当前页面全部已加载、可渲染的普通文本，并继续处理动态新增或变为可见的内容。

滑动窗口翻译和整页翻译只在最后获得焦点的 Chrome 窗口的活动标签页中运行。切换标签页或 Chrome 窗口时，插件会取消旧标签页的页面翻译请求并恢复原文，再由新的活动标签页按当前模式开始翻译，避免多个标签页同时消耗 API 并发和 Token。划词翻译不受此切换逻辑影响。

关闭翻译会立即取消正在进行的请求、关闭划词浮层并恢复页面翻译替换的原文。重新开启后，已打开的网页无需刷新即可继续使用。需要修改 API 配置时，点击控制面板中的“打开设置”。

使用滑动窗口翻译时：

- 插件会直接替换当前可见区域中的网页文字。
- 翻译期间右下角会显示当前区域的段落进度，并用淡蓝色标记正在处理的文字。
- 当前区域完成后会短暂显示翻译段数和耗时，随后自动隐藏。
- 页面滚动、窗口缩放或动态加载内容后，会继续翻译新进入视口且尚未处理的文字。
- 已翻译的文字再次进入视口时不会重复调用 API。
- 切换到划词翻译或关闭总开关时，会取消当前请求并恢复插件仍可安全识别的原文。
- 修改目标语言时，会恢复原文并使用新语言重新翻译当前可见区域。

滑动窗口翻译只处理顶层网页中的可见普通文字，不处理 iframe、图片、Canvas、SVG、视频字幕、表单控件、可编辑区域或代码块。它会分批调用模型 API，Token、延迟和错误继续计入控制面板中的现有监控。

使用整页翻译时，插件会在首次进入模式时处理页面中已经加载的全部可渲染普通文本，包括屏幕外内容。页面后续新增内容、原地更新的文本，以及通过 `class`、`style`、`hidden`、`aria-hidden` 或原生折叠区展开后变为可见的内容会自动翻译。短时间内的页面更新会合并后分批处理，重复通知不会重复请求；滚动本身不会触发扫描。已翻译且未变化的文本不会再次请求 API。

整页翻译按段落组织上下文：同一段落内被链接、加粗等行内元素分开的文字放在一起交给模型理解，按原文本节点写回，不替换元素、链接或事件。普通段落不跨批次；仅局部文字变化时，可附带该段原文作为上下文，已经成功且未变化的文字不会再次要求模型翻译。上下文也会产生输入 Token。

活动标签页按队列顺序逐自然段串行请求，当前段落及其补译全部结束后才发起下一段请求，不会把不同段落混入同一请求。段落只有一个文本节点时，直接使用纯文本请求，流式译文边返回边显示；包含多个文本节点时使用 JSON 批量请求，必须取得该段全部有效译文后才一次性写回。最终 JSON 损坏、ID 存在歧义、请求中断或补译仍失败时，不会保留该段的部分译文。

整页状态面板持续显示“正在请求”“正在补译 X/Y”、待处理数量或“当前无请求 · 监听页面变化”。当前段落最终失败后，面板会显示“翻译已暂停”，该页面不再请求后续段落；关闭翻译后重新开启可从原文重新扫描和重试。暂停期间仍记录页面新增或修改的内容，但不会自动恢复请求。关闭总开关或切换模式会停止该页面的监听并移除面板。监控中的 Token 是所有标签页的汇总，不表示当前页面仍在请求。每次 API 调用退出时都会清理网络连接；取消已发出的请求不保证服务商停止已开始的生成或计费。

每次整页请求只处理一个自然段，单段上限为 128 个文本节点、12000 字符。超过上限时保留该段原文、记录错误并暂停后续翻译，不拆分段落，也不越过它继续处理后面的内容。额外上下文每请求最多 12000 字符，超过预算时不附带额外上下文。整页请求超时为 60 秒，划词请求为 30 秒；流式请求在收到译文或思考片段时刷新超时计时，思考内容不展示、不存储，也不计入 TTFT 的首个译文时间。实际速度取决于页面结构、模型及服务端能力，段落上下文可以改善连贯性，但不保证模型译文质量。

批量 JSON 可解析且 ID 对应关系明确时，仅对缺失条目、缺字段或空译文的条目各补译一次。补译带上可用的同段上下文，要求只返回目标片段的纯文本译文，超时为 30 秒，不重复请求已经取得的条目，额外用量和延迟照常计入监控；补译在当前段落内串行执行，关闭翻译会一并取消。所有补译成功后才提交整个段落；任一补译仍失败则保留整段原文、暂停后续翻译并记录汇总错误。错误详情中的 `invalidItems` 和 `retryFailures` 会分别列出初始异常条目及补译失败原因，帮助定位模型返回格式或 API 问题。

使用官方 `api.deepseek.com` 的 `deepseek-v4-flash` 或 `deepseek-v4-pro` 时，插件为翻译请求显式设置 `thinking: {type: "disabled"}`，减少思考阶段的等待；批量翻译同时启用 `response_format: {type: "json_object"}`，约束模型输出 JSON。其他 API 和模型不附加这些参数；经第三方网关使用 DeepSeek 时，由网关决定思考模式。

遇到翻译错误时，控制面板日志会区分空译文、JSON 格式错误、批量条目数或 ID 不匹配、输出长度截断等原因。模型 API 报错会直接展示 HTTP 错误响应正文，或流式/非流式响应中的原始 `error` 内容；当前配置的 Token 和 Bearer 凭据会脱敏，超过 8192 字符的错误内容会截断并标注。展开“错误详情”可查看失败阶段、错误代码、API 主机、流式状态、HTTP 状态、返回字符数、耗时、模型结束原因及批量校验细节；旧日志没有详情，需要查看更新后产生的新日志。插件不主动记录原文、译文或思考内容，但服务端错误可能回显请求文本，分享日志前请检查。JSON 输出约束不能保证条目完整，插件仍会校验每个 ID，避免将译文写到错误位置。

插件不处理 Chrome 内部页面、Chrome Web Store、`input`/`textarea` 选区，也不提供翻译历史。

## 监控指标

控制面板的“延迟”页展示以下指标：

- `TTFB`：从发起 API 请求到收到响应头的耗时，包括浏览器网络处理、连接建立、服务端排队以及服务端开始响应前的时间。
- `TTFT`：从发起 API 请求到收到第一个非空译文片段的耗时，仅流式请求提供该指标。
- `完成耗时`：从发起 API 请求到完整译文接收完成的耗时；流式请求以收到 `[DONE]` 为终点，非流式请求以完整响应解析并确认译文有效为终点。
- `P50`：50% 的成功请求完成耗时不超过该值，反映典型请求体验。
- `P95`：95% 的成功请求完成耗时不超过该值，用于观察较慢请求的尾部体验。

历史平均完成耗时基于全部历史成功请求。P50 和 P95 基于最近最多 500 次成功请求。失败、超时和取消请求只计入请求结果数量，不参与平均值或百分位数计算。这些指标是浏览器侧观测的 API 请求耗时，不代表模型的纯推理耗时，也不包含 Token 统计和日志写入时间。

## 升级插件

如果插件目录是通过 Git 克隆的，在项目目录中更新代码：

```bash
git switch main
git pull --ff-only origin main
```

然后打开 `chrome://extensions`，找到本插件并点击“重新加载”。插件会为已经打开的普通 HTTP/HTTPS 页面自动恢复内容脚本，通常无需刷新网页；如果页面受 Chrome 注入限制或仍显示旧版本错误，请手动刷新该页面。保存在 Chrome `storage.local` 中的翻译服务配置会继续保留。

如果插件目录不是 Git 仓库，请用新版本文件完整覆盖原目录，再到 `chrome://extensions` 中重新加载插件。插件加载期间不要删除或移动该目录。
